# Character Engine M2B-1 — controlled succession and regency

26 October 2026. Implemented only `character-engine-m2b1-codex-handoff.md`, starting at `1ff281c`. **No production succession/fate triggers, replacement generation, new management controls, portraits or new literary dialogue.** The normal game never imports/calls the test executor. Original starts retain 23 people, eight original seats, unchanged character RNG, and absent succession/regency arrays.

## Candidate engine and decisions

`narrative-succession.js` builds on M2A `successionContext`, typed claims and family links. `assessSuccessor`, `evaluateSuccessors` and `selectSuccessor` return detached structured reasons/evidence, not mutated state. Candidate checks include known identity, alive/present condition, actual regional claim or explicit prior court-appointment evidence, supported claim status/standing/basis, compatible existing regional assignment and no conflicting occupied seat/regency. Institutional adviser NPCs cannot become rulers/regents. A sibling name, legacy `heir` category or marriage alone is insufficient.

Default editorial policy: adulthood **18**, minors allowed only with an eligible adult regent, recognised asserted claims, and a recorded active guardian as regency basis. Test policy can explicitly configure claim bases/standings, dormant claims, basis priority, a higher adult threshold or supported parent/adoptive-parent regency bases. Policy does not use names, gender, an unknown cultural succession law or hidden tiles. A sourced extraordinary **court** appointment can be tested for an existing person; Company appointments remain blocked. No unknown replacement is generated.

Selection returns `selected`, `none`, `ambiguous` or `invalid-choice`. With several equally eligible alternatives it returns a controlled-choice requirement. Optional explicitly supplied basis priority can distinguish tiers; lexical ordering is display stability, never a tie-breaking coronation. A minor with multiple eligible regents needs an explicit regent choice. A controlled override must still meet eligibility; it cannot install an unavailable character. No gameplay/narrative RNG or wall-clock selection. Tests trap both crypto RNG and `Math.random` and check exact replay, reordered request keys and detached preview evidence.

## Atomic transaction and provenance

`applyTestSuccession` validates before writing, clones the state, and emits one canonical **manual-test** `test-succession` incident with explicit request, participants, exit, claim/regent and actual regional snapshot. It then saves optional `n.successionRecords` and `n.regencies`. Incomplete/ambiguous/invalid input throws without changing any original field. Duplicate request IDs are idempotent; conflicting reuse is rejected. A labelled explicit test authorization is mandatory. There is no action button, Debug fate editor, normal action type or New Turn trigger for this API.

The single commit updates the seat, previous/new political roles and their source-linked history, selected claim to realised, incumbent realised claims to dormant, and participant incident journals. Explicit confirmed death alone writes the incumbent's alive → dead history and closes any existing marriage with recorded widowhood; abdication leaves them alive. No prior personality, family, house, relationship, quoted line, memory or legacy `role` category is overwritten. Old positional labels are archived in the transaction. Legacy regional-interest strings are not promoted to newly invented counterclaims.

The province's entire board state, control, overlord, presidency, strengths, orders, loot, Elephant, laws, phase and outcome remain unchanged. Company-dependent/vassal kinds are read from the actual map. Where an existing allegiance episode names the outgoing person, it is ended and a continuity episode names the new holder under the **same** existing political relation, with unknown personal origin/no transferred promises. This creates no treaty, conquest, fealty statement or relationship score; the original episode/words remain intact.

The former ruler's saved private outlook is archived **under its original owner**, with exact catalogue wording and owned-memory/source checks. It is removed from the active regional slot so the successor never inherits it or its fictional knowledge. New private assessments may occur only at the existing appropriate later committed transitions; no new thought is generated by succession selection or dossier reads. Minor titulary rulers under an active regency do not receive adult outlook/reaction presentation through these existing pipelines. No new regent dialogue is authored or substituted.

## Titular ruler and acting regent

`n.seats[region]` points to the titular ruler, including a minor. A separate optional tenure stores `id`, `successionId`, `region`, `rulerId`, `regentId`, start/end provenance, both recorded start ages, policy adulthood threshold and the regent's exact prior role/position. The regent must be a distinct available adult with actual recorded policy-supported guardianship/parental evidence, not another seated ruler, capital emperor, player officeholder or institutional adviser. No extra board seat is created.

`endTestRegency` requires a separately labelled committed synthetic event after the titular ruler reaches the stored threshold. New Turn still adds **3** once, but never ends a regency. The end event restores the adult's prior role/position, leaves the titular seat unchanged, and is itself idempotent/provenance-linked. The underlying recorded family relationship is not erased merely because the acting political tenure ends.

## Validation, archives and compatibility

Narrative **version 2** is retained. Both registries are optional, defaulted only by interpretation; old current-version saves are not migrated or backfilled. New current seats with a legacy family category need actual validated succession evidence. Existing dead/unavailable-seat checks remain. Validation binds records to canonical synthetic facts and saved request/policy/evidence, checks claim realisation and role/fate chains, current seat continuity, eligible start ages, unique/non-overlapping regencies and matching ending events. Orphaned sources and supporting-record deletion are rejected with named guards. Confirmed-dead candidates cannot revive.

Small source-time helpers reconstruct seats/conditions using only recorded changes. Existing approved dialogue, trade lines, anticipation snapshots and chapter validation now use the appropriate source holder/fate instead of mistaking the current successor for the past speaker. Old words are never rewritten to pass validation. Legacy character categories (`ruler`/`heir`/adviser) remain unchanged; the current-Rulers roster facet also includes the actually installed titular actor. Independent outlook aptitude for a recorded successor remains that person's own, not inherited.

Dossiers, roster/region summary and readable export distinguish former ruler, titular holder and acting regent, with recorded source/claims and a clearly labelled synthetic succession history. Canonical history reports are technical **SYNTHETIC TEST** output, not newly approved fictional prose. No additional narration acknowledgements or Read scene button.

## Deliberate limits / next milestone

No live trigger adapter is installed: canonical succession incidents are deliberately synthetic, never an inferred consequence of a battle, rout, New Turn or real conquest. No mortality probabilities, new characters, births, marriages, Company appointments, exiled/presumed-dead returns, impostors, emperor veto, feuds or conquest settlements. The current associated-region invariant is preserved; cross-region candidates need future approved representation rather than changing their existing regional assignment. An unresolved active regency must be ended before another succession in that region; incomplete exits reject safely rather than kill an incumbent and leave an invalid seat. Protected India resolutions/final games are not interrupted. Culture-specific policy, active triggers, regent-specific prose, child voice and fallback/new-ruler decisions remain for M2B-2 and creative review. **No hosted Site deployment.**
