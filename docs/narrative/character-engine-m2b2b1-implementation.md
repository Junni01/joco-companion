# Character Engine M2B-2b-1 — readiness and controlled court development

31 October 2026. Delivered only the [approved handoff](character-engine-m2b2b1-succession-readiness-handoff.md). **No live recognition, court appointments, people, deaths, births, marriages or automatic regency changes. No production dialogue, rules or UI changes. No Site deployment.**

## Pure readiness

`narrative-readiness.js` extends the actual M2B-1 evaluator rather than replacing it. `successionReadiness(state,region,policy)` and `regionalReadiness(state)` are deterministic and detached. Primary statuses: `ready-adult`, `ready-minor-with-regent`, `contested`, `needs-documentation`, `needs-candidate`, `blocked-regency`, `blocked-regency-choice`, `blocked-cross-region` or explicit game/pending/authority structural blockers. `transactionReady` is separate from a selected candidate. Per-candidate reasons/evidence remain in `candidateBlockers` and `decision`; rejected alternatives do not block an otherwise valid selected adult. An active regency blocks even when other claimants remain eligible.

All eight untouched seats report **needs-documentation**, with their existing sibling evidence, not recognised heirs. Potential documentation is supported by saved legacy sibling links, typed family evidence or a recorded relevant court role; it does not invent a parent or witnessed event. A legacy `heir` category alone supplies no claim. Unknown/unavailable/occupied/foreign/institutional people cannot become a potential successor. Court-development policy permission is separate: Company regions retain their M2B-1 existing-claim succession semantics but cannot use this new court power.

## Controlled recognition and introduction

`narrative-court.js` contains **test-controlled writers only**. It is absent from app/actions/deploy/phase/setup imports. Every call requires `{mode:'synthetic-test',label:'...'}` and validates the entire input/output. No wall-clock/random draw, preview side effect or automatic trigger. Terminal games and protected India progress reject new transactions. Exact replay of an already committed request returns the input unchanged, even after later progress; a conflicting reuse rejects.

- `recognizeTestHeir`: named available known person, same region, no incompatible occupied office, a currently present coherent ruling authority, explicit purpose; writes a new recognised designation/witnessed-authority claim. Existing compatible dormant/unrecognised claims need an explicit prior claim ID, retain their original basis/origin/support and save prior status plus a sourced status transition where needed. Conflicting live recognition and fake parentage/adoption bases reject. Another person can be explicitly recognised, producing a genuine contest rather than silently displacing a claim. No seat, kinship, personal trait, relationship or loyalty changes. The new incident is the recognition, never proof the person was always heir.
- `planCourtCandidate`: reuse eligible known claimant; otherwise prefer a supported existing person needing recognition. It refuses unresolved ties, protected/terminal/active-regency boundaries, cross-region claims, unresolved living claims and Company court authority. Only a genuine remaining gap permits introduction. Confirmed-dead old claimants are retained historically but cannot veto all future candidate development forever.
- `introduceTestCourtCandidate`: explicitly supplied `Synthetic ...` name, unique ID, adult age 18–100; introduces a **minister**, not ruler, with introduced-age/source/region/purpose and a witnessed-authority claim. Fixed neutral test traits/voice/pacing are initialized independently (no RNG or copied personal history). Empty memories, relations, family, legacy claims and development histories; no dynasty/gender, inherited quotations or Parliamentary interests. Production naming/biography/personality policy remains C01/editorial work. The current authority is the existing Indian local ruler, including a vassal; no imperial approval or Company power is inferred.

Authority support is deliberately narrower than every conceivable court: collective court institutions and automatic compatible real-event/Leader adapters are not implemented. The controlled incident itself records a witnessed synthetic ruling authority. A real Leader event still changes only its existing rules result; no hook recognises a sibling.

## Atomic emergency boundary and provenance

`applyTestEmergencySuccession` requires a separately supplied labelled synthetic-fixture warrant and explicit `confirmed-death` or `abdication`, never an inferred battle casualty or age threshold. It reuses one supported existing person where possible, or introduces a minister only if genuinely needed, then calls the existing M2B-1 atomic successor writer. Multiple potential people need explicit controlled recognition first; no lexical/gender tie selection.

One returned state / one caller Undo boundary contains **two ordered supporting incidents** when recognition/introduction is needed: `test-court`, then `test-succession`. This respects the existing requirement that claim evidence precede succession. The local intermediate state is valid and still has a living incumbent; it never escapes the wrapper. Any failure leaves the caller's input byte-identical; there is no dead-incumbent/vacant-seat intermediate save. The final succession request links `courtRecordId` and the exact emergency request/warrant; both are validated against the candidate, region, authority, purpose and actual exit. Reuse of an already eligible claimant needs only the existing succession incident.

Optional version-2 `n.courtRecords` saves request ID, kind, region, authority/candidate IDs, recorded age/role, purpose, board snapshot, canonical origin, claim-after snapshot, optional prior claim and independent introduction snapshot. The same record is linked to a canonical manual-test fact; duplicate/missing/orphaned records, altered sources, fabricated identity/claim state and malformed registries reject. Claim/role/life histories continue using M1/M2A/M2B-1 validators. Named deletion guards include new and prior sources. No existing record or dialogue is reworded; private outlook ownership remains with the former ruler through M2B-1 archives.

No migration, backfill or version bump: untouched v2 saves remain untouched, with no new registry until a controlled commit. Normal starts still have 23 identities/eight original seats and identical character RNG. Normal/quiet/Debug behavior and storage separation are unchanged. Existing dossier/claim/source projections display imported synthetic records read-only; no UI button/prompt/control was added.

## Explicit exceptional blocking contracts

The handoff permits tested blocking contracts where implementation would expand the existing model. These remain **unimplemented transitions**, not claimed as solved:

1. **Titular death/deposition during active regency:** M2B-1 requires no active regency at accession. Its tenure ending currently requires adult readiness and restores the regent's exact prior office. A safe future design must add a sourced non-adulthood end reason, close old tenure/roles and choose the new titular/regent within one atomic boundary; it must not promote the regent by default. This task rejects the attempt without changing the old seat/tenure.
2. **Regent becomes unavailable/replacement:** current validation requires the active regent alive/available; every tenure start is linked to a succession, and adult-only tenure closure cannot represent mid-reign replacement. The contract returns any separately documented eligible second guardian with evidence, but no new tenure is written. Tests include an eligible second guardian and unchanged original state after rejection. A tampered missing active regent is rejected rather than loaded as a corrupted court. Future work needs a sourced unavailability+replacement request and tenure linkage without a fabricated new succession.
3. **Foreign-region claimant:** legitimate claim remains inspectable but M2B-1 associated-region prohibition stays. Future design must explicitly record regional reassignment/office conflicts while preserving historic regional attribution and one seat per person. No casual `character.region` rewrite.
4. **Equally eligible claims/regents:** preserve every claimant and source; report contested/tenure-choice block. Future approved local priority policy or an explicit controlled fixture choice could resolve it. Names, gender and unknown custom never settle it. No new grudge or political rebellion is inferred.

Company-dependent court development, imperial/relationship-driven conquest settlements, cultural naming, biographies, court collective authority, live event adapters, live mortality and all later b-2/b-3 features remain separate approvals.
